# Writing Guide

Welcome to the central guide for creating and contributing documentation. The goal of this guide is to help team members write clear, consistent, and helpful content using the features available in our Docusaurus site.

Well-written documentation is crucial for our users and for ourselves. Following these guidelines will ensure a high-quality and maintainable docs site.

## Key Principles

- **Clarity:** Write in simple, clear language. Avoid jargon where possible, or explain it if necessary.
- **Consistency:** Use consistent terminology, formatting, and structure across all documents.
- **Completeness:** Ensure that documents provide all the necessary information for the user to accomplish their goals.
- **Audience-Awareness:** Write with the target audience in mind. Are they beginners or experts?

## Style guide

- **Tone:** Friendly, professional, and concise. Prefer active voice. Avoid idioms.
- **Capitalisation:** Use sentence case for headings. Proper nouns are capitalised (e.g., Git, AWS, Docusaurus).
- **Spelling:** Prefer British English (colour, organise, programme). Avoid US spellings (color, organise).
- **Numbers and units:** Use SI units and spaces, e.g., 10 MB, 2 hours. Avoid mixing units.
- **Dates:** Use ISO-8601 or clear formats, e.g., 2025-08-16 or 16 August 2025. Avoid ambiguous forms like 08/09/25.
- **Code:** Keep lines short `(<100 chars)`, add titles where helpful, highlight key lines.

## Docusaurus Features

Our site is built with [Docusaurus](https://docusaurus.io/), a modern static website generator. It provides several powerful features for documentation.

### Admonitions

Use admonitions to highlight important information.

<details>
<summary>Show Admonition Code Snippets</summary>

```markdown
:::note
This is a note.
:::

:::tip
This is a tip.
:::

:::info
This is for information.
:::

:::warning
This is a warning.
:::

:::danger
This highlights a danger or critical warning.
:::
```

For more details, see the [Docusaurus Admonitions documentation](https://docusaurus.io/docs/markdown-features/admonitions).

</details>

### Tabs

Use tabs to show information in selectable panels, which is great for showing code in multiple languages.

<details>
<summary>Show Tabs Code Snippet</summary>

```mdx
import Tabs from '@theme/Tabs';
import TabItem from '@theme/TabItem';

<Tabs>
  <TabItem value="js" label="JavaScript">
    console.log("Hello, World!");
  </TabItem>
  <TabItem value="py" label="Python">
    print("Hello, World!")
  </TabItem>
</Tabs>
```

For more, visit the [Docusaurus Tabs documentation](https://docusaurus.io/docs/markdown-features/tabs).

</details>

### Code Blocks

Use code blocks for displaying code with syntax highlighting.

<details>
<summary>Show Code Block Snippets</summary>

````markdown
```python
def hello_world():
    print("Hello, from a code block!")
```
````

You can also add titles and line highlighting. See the [Docusaurus Code Blocks documentation](https://docusaurus.io/docs/markdown-features/code-blocks).

</details>
